# 腕上提醒的点过程强度张量与区间校准

这里的腕表和手机的规范事件是用于设备联调的合成资料。使用 Node.js 22。运行 `npm ci --offline` 核对依赖锁，`npm run inspect` 查看资料字段，`npm test` 检查资料格式及相互引用。检视脚本只读取元数据。

## 数据格式

强度 λ_k(t)=base_k+Σ_{s<t}Σ_r A[k,type_s,r] exp(−decay_r(t−s))，所有 A、decay、base 非负且 decay>0。每读数是左极限；同一时刻所有事件只影响恰后时刻。观测窗口是半开并给出独立类别掩码。完整有序事件的对数似然是窗口内 log 左极限强度之和减观测域内对应强度积分。梯度仅对 `A`、`decay`、`base`；有不确定过去的窗口可以报告未校准。区间强度证据必须对身份合并后所有允许的 t 成立，宽于资料 tol 时不能签正式提醒；容许提供合理更紧的界。event-pages.mjs 给源时间与断连点，重叠设备 ID 先由同一个 pulseKey 证明。重复页也占 reReads。 输入事件时间和衰减单位均为分钟。相同 pulseKey 的报告若区间相交，真实时间属于其交集，区间完全分离则先报告设备身份争议。采集缺失不允许自行假定暗中发生的事件，强度范围的合同只覆盖驱动送达的有界事件及可重读的已知历史。校准的一整段需要所有相关确证事件，这是一个可被供应方重新声明的条件。 同佩戴动作的 timeLinks 由设备耦合记录给出，格式 [earlierKey,laterKey,minDelta,maxDelta]。使用同一物理时间变量解释这些边。只要约束仍可满足，待确认的数值区间要包含所有合法时间排列，且单个活动的范围宽过 tol 时报告需要关联补片，不能自称达到设备精度。活动概率读出另使用该时段积分计算一次触发概率 1−exp(−integral)，补片若改变接近决策线的历史尾部则下一次校准必须反映改变的通道。 补片包含 corrected 及 linked 的两条记录，补入事件仍须与 timeLinks 共同解释。区间状态的实时结果需要指出仍可能改同一触发结论的输入事件身份，以便驱动优先补合。 alertThresholds 中的 t 为瞬时读点，horizon 是 [t,t+horizon) 的概率窗口。instant 和 risk 都需达到标准才确认触发，若有一个上界低于门限则正式不触发，其他情况等待。当前已确认事件不应因另一通道独立处在缺测域而改变已确认时间。fillInterval 的补片来源为 H，经与 P 的 pulseKey 及 timeLinks 归并。

## 取数

`inputs/event-pages.json` 保存标定、规格和调用记录。记录中的范围除明确说明外从零开始，使用半开区间。批量数组按调用记录列出的顺序交付。eventPage(page) 给设备原始事件和观察范围，hazardCoefficients(target,source) 给激励系数行。
